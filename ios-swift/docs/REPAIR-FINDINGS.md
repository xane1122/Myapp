# Beta 使用问题调查（2026-09-13）

## 已确认的事实

- 用户手机里的壁纸是新换的目标壁纸；桌面和 Beta 显示的是旧壁纸。
- 当前线上 `static/wallpaper.js` 的 `setFile`、`setConfig`、`reset` 只操作当前来源的 localStorage；没有上传或下载壁纸设置的请求。设置页调用这些函数，不会同步图片到 GitHub 或服务器。独立 Bundle ID 的 Beta 也不能直接读正式 App 的沙盒。
- 线上首页 `init()` 同时启动 `loadConversations()` 和 `loadHistory()`。全新存储的 `currentConversationID` 为 0；读取历史时尚未等会话列表选择有效 ID。实际只读请求 `/api/history?conversation_id=0&limit=1` 返回 HTTP 400；会话列表返回 HTTP 200。该错误可以解释新设备的首次历史加载失败，但尚不能排除手机上的其他网络问题。
- `openAssistant()` 同样先捕获 ID 再异步加载列表；列表改变当前 ID 后，最近消息加载的校验会提前退出。应在确定有效会话后加载，而不是重试无效 ID。
- 首页每次初始化会注销所有 Service Worker、删除所有 CacheStorage，再注册。这会反复丢失静态资源缓存，是可确认的重复下载路径；手机实际每项资源耗时仍待设备验证。
- 提示原文包含「历史记录加载失败，暂无本地缓存」，不等于本地存储已损坏。调查没有删除任何设备缓存。
- 当前公开健康接口 HTTP 200、`status: ok`。2026-09-14 在取得本回合网络/固定密钥读取权限后，SSH 已成功，已核验远端工作区状态和 AGENTS.md，服务健康 ok；既有大量未提交修改保留，相关文件 diff 仍须在实施前逐项核对。

## 网站修复范围（用户已授权，尚未实施）

实施前必须重新读取远端 AGENTS.md、当前文件和 diff，在保留既有修改的基础上合并。以下为具体接口设计与候选文件，不代表已修改或部署。

1. `static/index.html`：首次加载及切换助手时先获得有效会话 ID，再请求历史；保留缓存先展示、最近消息优先、后台合并完整记录，以及用户翻看旧消息时不抢滚动位置。取消每次启动注销/清空全部静态缓存，交给现有 Service Worker 版本更新流程管理。`static/sw.js` 更新缓存版本。无需更改聊天 API、模型或数据库。
2. `static/wallpaper.js`：保留即时本地应用，同时读取/写入服务器外观版本；初始化时服务器无记录就保留本地，禁止空值覆盖。只同步壁纸图片、页面目标、位置、缩放和图标色，不上传其他 localStorage 字段。
3. `static/settings.html`：显示保存结果、同步失败重试与冲突状态；增加「将这台设备的壁纸同步到其他设备」迁移入口。旧数据没有可靠修改时间，因此不能让电脑旧壁纸在首次启动时自动上传，覆盖手机新版。先在装有新壁纸的手机中明确执行一次迁移，之后服务器版本成为同步基准。
4. Go HTTP 路由所在文件及新增 `appearance.go`（实际目录待 SSH 核验）：新增 `GET /api/appearance`、`PUT /api/appearance`，保留远端 AGENTS.md 要求的永久免登录，通过精确 Origin 校验、JSON 请求、输入约束和限流保护写接口，不新增登录、密码或会话门槛；读取返回 `revision` 和各页面外观，写入使用 `If-Match` 做版本比较，不一致返回 409，禁止无条件最后写入覆盖。
5. 不改生产聊天数据库。外观使用单独的私有持久文件，存放在生产数据目录（最终路径待核验），采用锁、临时文件和原子替换；部署必须保留文件，写前备份。沿用当前单站点外观作用域，不引入新的账号或登录机制；不能以任意客户端用户 ID 选择服务器文件路径。

请求示例（图片为占位，不是用户壁纸）：

```http
PUT /api/appearance
If-Match: "revision-4"
Content-Type: application/json

{"target":"home","appearance":{"image":"data:image/jpeg;base64,...","x":50,"y":50,"zoom":1,"iconColor":"#cfaeb5"}}
```

服务端校验页面目标白名单、图片实际解码类型/尺寸/大小、位置与缩放范围；图片只允许受限 raster 格式，拒绝 SVG 和任意 URL。每次只更新一个目标，恢复默认使用显式 tombstone 并增加 revision。限制总体文件大小；多设备冲突不丢弃本地待同步值。

影响：网站更新后正式 App、Beta 和电脑都会获得相同的初始化修复和外观同步；旧 App 二进制、Bundle ID、模型配置、密钥和聊天数据库不动。增加外观接口需要重新构建并重启网站服务，用户 2026-09-14 已表示「后续允许一切」，本任务所需改动已获授权；执行前仍须审阅差异、备份和测试。回滚前备份源码和外观文件，不删除手机本地壁纸。
